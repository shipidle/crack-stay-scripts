# 캐릭터 상태 삽입기

최근 대화에서 내 캐릭터와 현재 등장인물의 **복장·자세·위치·소지품**을 읽고 다음 내 메시지에 짧은 상태표를 덧붙임. 전송 버튼을 대신 누르지 않음.

## 설치와 설정

1. [설치센터](../INSTALL.md)에서 **캐릭터 상태 삽입기** 설치.
2. 로어인젝터도 쓴다면 유저스크립트 관리자의 실행 순서에서 **상태 삽입기를 로어인젝터보다 먼저** 배치하고 Crack을 새로고침.
3. 채팅방 오른쪽의 **🧍 상태 → 모델·자동 갱신 설정** 열기.
4. Vercel AI Gateway API 키와 모델 ID 입력 → **설정 저장 → 지금 갱신**.
5. 상태표와 **삽입 미리보기** 확인 후 평소처럼 채팅.

기본 모델 ID는 `google/gemini-3.1-flash-lite`. [Vercel 모델 목록](https://vercel.com/ai-gateway/models)에서 지원하는 모델 ID를 복사해 직접 변경할 수 있음. 구조화 JSON 출력을 지원하는 모델이 필요함. API 키는 이 스크립트 설정에 별도로 입력하며 다른 스크립트에서 가져오지 않음.

## 기본 동작과 비용 절약

| 설정 | 기본값 |
|---|---|
| 처음 읽는 대화 | 최근 5왕복 턴 (내 말 + AI 답변 = 1턴) |
| 갱신 간격 | AI 답변 완료마다 1회 |
| 인물 수 | 최대 4명 |
| 삽입문 | 최대 600자 |
| AI 출력 한도 | 600토큰 |
| 입력 대화 예산 | 12,000자 |
| 상태 만료 | 30분 |

처음에는 최근 대화를 읽고, 이후에는 **직전 상태 + 새 대화**만 분석함. 대화가 그대로면 새로고침하거나 ‘지금 갱신’을 눌러도 추가 AI 요청을 하지 않음. 12초마다 대화 완료 여부를 확인하는 작업 자체는 Vercel AI 호출이 아님.

비용을 더 줄이려면 갱신 간격을 2~3왕복으로 늘릴 수 있음. 이 경우 다음 갱신 전까지 이전 상태가 삽입될 수 있음. 입력/출력 한도도 조절 가능하지만 너무 작으면 일부 맥락을 놓치거나 응답이 잘릴 수 있음. 실제 비용은 모델과 사용량에 따라 달라지므로 Vercel 대시보드에서 확인. 패널의 호출 수에는 실패한 시도도 포함하며, 토큰 수는 API가 반환한 사용량 기준임.

## 직접 수정

- 상태를 고치고 **수정 저장**을 누르면 즉시 반영됨.
- 각 항목의 **고정** 체크는 이후 자동 분석보다 우선함. 옷이 바뀌면 고정을 풀거나 직접 고쳐야 함.
- **현재 장면에 있음**을 해제한 인물은 삽입하지 않음. AI가 이후 다시 등장했다고 판단하면 재등장할 수 있음.
- **이 방 초기화**는 이 스크립트의 해당 방 상태를 초기화함.
- 자동 갱신/자동 삽입을 각각 끌 수 있음. 완전히 중지하려면 스크립트를 비활성화하고 새로고침.

## 로어인젝터와 함께 사용

[참고 로어인젝터](https://github.com/Localsmile/CRACK-INJECTION-REFINER)의 등록 함수와 저장소를 덮어쓰지 않음. 기존 WebSocket 전송 함수를 이어 호출하며, 원문·로어를 자르거나 채팅을 재전송하지 않음. 상태표는 독립 표식 `[[SHIPIDLE_SCENE_STATE_V1]]`로 구분함.

**실행 순서가 중요함.** 상태 삽입기가 먼저 설치되면 로어 처리 완료 후 남은 예산에 상태표를 붙임. 원문+로어+상태가 2,000자를 넘으면 상태만 생략함. 반대로 로어인젝터가 먼저 설치되면 로어 예산 보호를 위해 상태 삽입을 생략하고 패널에 순서 변경 안내를 표시함. 단순한 설치 날짜보다 관리자의 실제 실행 순서가 중요하며 변경 후 새로고침 필요.

답변 생성 중·상태 갱신 중·오류·오래된 상태·직전 메시지 불일치 때도 상태를 생략함. 채팅 전송은 AI 분석을 기다리지 않음. 따라서 빠르게 다음 메시지를 보내면 상태표가 없을 수 있음.

## 검증 범위와 제한

- 참고 저장소의 실제 전송 인터셉터(분리본/통합본)를 사용한 모의 검사: 양쪽 실행 순서, 원문/로어 보존, 전송 1회, 중복 상태 방지 통과.
- 리롤/삭제 시 재구성, 생성 중 대기, 실패한 대화 자동 재청구 방지, 탭 간 중복 호출 방지, 분석 도중 직접 수정 보호 검사 통과.
- 로컬 브라우저에서 설정 패널·수정·고정·삽입 미리보기·모의 전송 확인.
- **실제 Crack/Stay/iPhone과 실제 유료 API 호출은 아직 검증하지 않음.** 테스트의 전송/API는 모의 환경임.
- 확인된 Crack WebSocket 전송 경로만 지원함. 사이트가 HTTP 등 다른 경로로 전환하면 삽입하지 않음.
- 탭 간 잠금(Web Locks)을 지원하지 않는 브라우저는 AI 호출을 중지함.
- 상태는 채팅방별로 현재 브라우저에 저장됨. 추측을 금지하는 프롬프트를 사용해도 AI 분석 오류는 가능함.
- API로 보내는 내용은 최근 대화와 이전 상태이며, 설정한 Vercel 모델로 전달됨.

개발 검사: `node scripts/test-character-state.mjs`. 외부 참고 코드는 저장소에 복사하지 않으며 `--lore <인터셉터 파일 경로>`로 추가 검사 가능.
